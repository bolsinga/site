# site

A SwiftUI app (macOS, iOS, tvOS) that shows the shows in the JSON generated by [web_generator](https://github.com/bolsinga/web_generator), which is not in this repo.

## Layout

- `Sources/Site` is the app's UI and model. `Sources/App` is the app target, `Sources/Intents` holds App Intents, and `SiteWidgets` holds the widgets.
- `Shared` is a Swift package with the data model, shared with the widgets.
- Tests are in `Tests/`: `SiteTests`, `MusicDataTests` and `UtilitiesTests`. Tests that import only `Shared` are in `Shared/Tests/SharedTests`, run with `swift test --package-path Shared`.

## Building and testing

- Build and test with Xcode's tools (`BuildProject`, `RunSomeTests`), not `xcodebuild`. The scheme is `SiteApp`, and the test target is `Tests`.
- Check a change builds for My Mac, the iOS simulator and the tvOS simulator, as CI does. CI also runs the tests on macOS.
- Never test on a physical device. Use My Mac or the simulators, and switch the run destination back to My Mac afterwards.
- The deployment target is 27.0 everywhere, so new APIs can be used. tvOS lacks some, such as `dismissalConfirmationDialog` and the document APIs, so guard them with `#if !os(tvOS)`.
- Builds update `Localizable.xcstrings`; commit that change with the code.
- Warnings MUST NOT get in. The project treats Swift and C warnings as errors, but a few, like a type used without importing the module that declares it, are still only warnings. Fix every warning a build shows, and import what a file uses.
- Rebuilt widgets on macOS keep running the old code until `killall SiteWidgetsExtension`.

## Code

- Indent with 2 spaces.
- Keep comments to one line. Put the reasoning in the PR description. Code comments should be used sparingly, only to document something unusual. Code comments should not describe the code in prose.
- Reuse or extract existing helpers rather than reimplementing a lookup or a format.
- Tests use the Testing framework.
- Format the whole code base before pushing each commit: `xcrun swift-format format --in-place --recursive Sources Shared/Sources Tests SiteWidgets`. It uses the default configuration, the code base is already formatted, and CI fails a change that `swift-format` would alter.

## RFCs

Design decisions and rules are in `docs/rfc/`, one file per area, named `NNN-name.md` with up to three digits. Read the one for the area you're changing. A change that alters a documented rule updates its RFC in the same PR.

- [`docs/rfc/001-venue-places.md`](docs/rfc/001-venue-places.md): the Venue Places window, `venuemap.txt`, and the Maps and website checks.
- [`docs/rfc/002-mapkit-geocoding.md`](docs/rfc/002-mapkit-geocoding.md): MapKit geocoding, identifiers and caching, in general and as the site app and Venue Places use them.
- [`docs/rfc/003-navigation-entry-points.md`](docs/rfc/003-navigation-entry-points.md): URLs, Handoff, intents, Spotlight, widgets and quick actions, and how they reach the same screens.
- [`docs/rfc/004-archive-path-category-navigation.md`](docs/rfc/004-archive-path-category-navigation.md): `ArchivePath` and `ArchiveCategory`, their string and URL forms, and the `ArchiveNavigation` state that holds them.
- [`docs/rfc/005-music-loading.md`](docs/rfc/005-music-loading.md): when the music is downloaded or read from the cache, and how a load replaces the last.
- [`docs/rfc/006-precomputed-music-data.md`](docs/rfc/006-precomputed-music-data.md): what is computed in advance from the music, saved with it, and kept out of it.
- [`docs/rfc/007-shows-today-widget.md`](docs/rfc/007-shows-today-widget.md): the Shows Today widget, its snapshot in the app group, publishing, the timeline and links.
- [`docs/rfc/008-nearby-location-filter.md`](docs/rfc/008-nearby-location-filter.md): the Nearby and City filters, the location and current city, and what each state shows.
- [`docs/rfc/009-entities-siri-spotlight.md`](docs/rfc/009-entities-siri-spotlight.md): the App Intents entities, their queries, the Siri shortcuts, and how Spotlight is kept in step with the archive.
- [`docs/rfc/010-today-and-day-of-leap-year.md`](docs/rfc/010-today-and-day-of-leap-year.md): the day of the leap year, what today is, and how the Today screen pages between days.
- [`docs/rfc/011-persisted-state.md`](docs/rfc/011-persisted-state.md): everywhere the app keeps state (scene and app storage, caches, the app group, the Spotlight index), who owns it, and what versions it.
- [`docs/rfc/012-maps-and-clustering.md`](docs/rfc/012-maps-and-clustering.md): what each map shows, how venues cluster, when a snapshot map is used, and how maps relate to the location filter.
- [`docs/rfc/013-rankings-first-sets-and-library-order.md`](docs/rfc/013-rankings-first-sets-and-library-order.md): what rankings, first and most recent sets, and library order mean, and how they are shown.
- [`docs/rfc/014-search-and-sharing.md`](docs/rfc/014-search-and-sharing.md): in-app search, how matching and emphasis work, and what sharing produces.
- [`docs/rfc/015-ci-and-release.md`](docs/rfc/015-ci-and-release.md): the CI and release workflows, the build and test matrix, and how versions are set.
- [`docs/rfc/016-testing.md`](docs/rfc/016-testing.md): how the project is tested, the conventions in use, and what is not covered.
- [`docs/rfc/017-site-tool.md`](docs/rfc/017-site-tool.md): the command-line tool in the app binary, its commands, and the diary data it reads.
